# Experimental RM binding version 1

This directory contains the machine-readable design for the repository-owned
fictional RM binding. It is an experimental research fixture under the reserved
`vc4qi.example` namespace. It is not an external standard, accreditation statement,
legal authorization or production integration.

The [manifest](manifest.json) covers the twelve categories required by the
[binding design](../../../docs/bindings.md): identity/governance,
carrier/schema, fact mapping, cardinality, discovery/integrity, recognized types,
principal/rights, scope/mapping, routes/restrictions, protection/time/resolution,
support/disclosure and evidence/exclusions. Its [schema](manifest.schema.json)
closes the top-level structure.

The two contexts and nine schemas are pinned in [`catalog.json`](catalog.json) (SHA-384
SRI over exact bytes). Signed controller documents, credentials and status lists are in
[`test-vectors/`](test-vectors/README.md), and `evaluateRmSlice` (Python
`evaluate_rm_slice`) evaluates them through gates 0–6. `installation.status` stays
`incomplete` until an independent proof-suite transformation vector is in place; see
[status](../../../docs/status.md#open-issues).

- The manifest's `scopeAndMapping.broader` is the binding's governed concept hierarchy
  (`skos:broader` pairs, applied transitively): accreditations A and H name sets
  (non-ferrous metals and alloys, element contents, solid forms), as an annex does,
  and contain the members the hierarchy places under them. It is binding governance,
  like units and method revisions, not something a credential can assert.
- [`resources/contexts/rm-1.jsonld`](resources/contexts/rm-1.jsonld) is hand-authored,
  `@protected`, uses the `rm:` prefix (the VCDM 2.0 context already protects `exp`),
  types every quantity, bound and uncertainty as an `xsd:decimal` string, and makes
  `materials`, `materialPropertiesList` and `results` ordered lists so that result
  order, and therefore native index pointers, is covered by the signature.
- [`resources/contexts/recognized-entities-draft-20261104.jsonld`](resources/contexts/recognized-entities-draft-20261104.jsonld)
  is a hand-authored stand-in for the W3C Recognized Entities context, which is not yet
  published: its terms expand to the draft vocabulary
  (`https://www.w3.org/ns/credentials/recognized-entities#`, Working Draft of
  4 November 2026), and `mainScope`, `activity` and `standard` are RM binding terms. It
  is used only by recognition `R` of the fictional Global ACI stand-in, which A, A2 and
  H point up to through `termsOfUse`; the RM context defines the type
  `RecognizedEntityCredential` for that reference. Replace it with the published context
  and re-sign when the W3C publishes one.
- `resources/schemas/*.json` and `catalog.json` are generated by
  [`scripts/rm-v1/build-resources.mjs`](../../../scripts/rm-v1/build-resources.mjs);
  run it with `--check` to detect stale output. Do not edit them by hand.
- The VCDM 2.0 context is the repository's existing vendored copy. Comparison with the
  hash W3C publishes for that context has not been performed in this environment. No runtime should resolve the
`.example` URLs over the network. Installed evaluator identifiers name reviewed
local procedures; they are data selectors and never issuer-supplied executable code.

The repository-root v1 contexts, schemas and credentials implement the legacy model
and are never treated as this binding. See [bindings](../../../docs/bindings.md) for how
the RM, calibration and GS bindings relate.
